# r3ad

3D-читалка и 3D-блокнот. Полное описание проекта — в [SPEC.md](SPEC.md).

**Текущая веха: M1 — настоящая книга и перелистывание.** Что работает:

- **EPUB 2 и 3, txt, markdown** — разбор целиком в браузере: zip, OPF, spine, оглавление из `nav`
  или NCX, санитайзер по белому списку, иллюстрации внутрь страницы;
- процедурный том, у которого толщина выведена из числа страниц, а не задана константой;
- разбивка текста на страницы средствами браузера (multicol) с честным пересчётом при смене набора;
- растеризация страницы в текстуру через `foreignObject` со вшитыми шрифтами и картинками;
- **переворот листа**: изгиб по цилиндру в шейдере, лицо и оборот на одной геометрии, просвет,
  контактная тень, пружина с инерцией;
- **перетаскивание страницы**: `t` берётся из положения курсора, а не из таймера — лист можно
  остановить на середине, довести или отпустить обратно;
- воркспейс: навигатор с оглавлением, инспектор набора и источника, тулбар листания, drag-and-drop;
- кэш текстур с вытеснением по LRU.

Демонстрация вехи: открыть свой EPUB и подвигать «Кегль» — том пересчитывается и физически
толстеет; страницу можно взять пальцем и перелистнуть.

## Запуск

```bash
npm install
```

```bash
node scripts/fetch-fonts.mjs
```

```bash
npm run dev
```

Шрифты (Literata, Inter — обе под SIL OFL) не хранятся в репозитории: скрипт скачивает нужные
подмножества с Google Fonts и пишет `public/fonts/manifest.json` с их `unicode-range`. Манифест
нужен не только для загрузки — по нему растеризатор решает, какие подмножества вшивать в
конкретную страницу.

Книги для проверки разбора собираются скриптом — с процентами в путях, расхождением регистра
и прочими ловушками, на которых конвейер однажды спотыкался:

```bash
node scripts/make-fixtures.mjs
```

## Что выяснил спайк M0

Растеризация страницы в текстуру была главным риском проекта (SPEC §19). Она работает, но путь к
ней оказался уже, чем ожидалось, — ограничения, каждое из которых молча ломает результат:

| Что | Наблюдение | Следствие |
|---|---|---|
| Адрес SVG | `blob:` помечает картинку как cross-origin, `texImage2D` падает с SecurityError | Только `data:` |
| Приёмник | `ImageBitmap` из SVG теряет origin-clean даже когда `<img>` его сохранил | Только 2D-холст, ~1.8 мс |
| `font-display` | При `block` и при `auto` текст внутри SVG не рисуется совсем — страница выходит пустым фоном | Только `swap` |
| Шрифты документа | Гарнитура из `document.fonts` внутри SVG-картинки недоступна | Вшивать обязательно |
| Иллюстрации (M1) | Внешние адреса внутри SVG-картинки не грузятся; `data:`-картинки рисуются | Вшивать каждую |

Проверено, что подставляется именно вшитая гарнитура, а не запасная: контрольная строка даёт
2126 закрашенных пикселей против 1568 у serif и 1893 у Georgia.

Ещё три находки M0, стоившие отдельной отладки:

- **`requestAnimationFrame` — плохой способ отдать управление между главами.** Он привязан к
  отрисовке, которую тормозит наш же 3D-вьюпорт, а в скрытой вкладке перестаёт вызываться вовсе:
  вёрстка растягивалась с 0.5 с до 16.6 с. Заменено на `scheduler.yield` / `setTimeout`.
- **Дети `<Canvas>` живут в отдельном React-корне, и он коммитит не тогда, когда ожидаешь.**
  Компонент внутри сцены, подписанный на zustand, не перерисовывался, пока по вьюпорту не
  щёлкнут мышью. Отсюда два следствия. Первое — сцена сделана чистой функцией от пропсов,
  состояние читается снаружи, в `Viewport`. Второе — от `frameloop="demand"` пришлось отказаться:
  в этой связке R3F 9 / React 19 он не доводит работу своего корня до коммита вовсе. Вернуться к
  нему стоит на M7. Заодно `<Environment>` вынесен в собственную границу `Suspense` — иначе он
  подвешивает всю сцену, пока собирает карту.
- **Композитор — общее состояние.** Две страницы разворота заказываются одновременно и
  перематывают его друг под друга; обе стороны выходили с одинаковым текстом. Отрисовка
  выстроена в очередь.

## Что выяснил M1

### Восемнадцать миллисекунд на форме записи цикла

Растеризация страницы стоила 45 мс при бюджете 40. Разбивка времени показала неожиданное:
21 мс уходило не на отрисовку, а на **сборку строки** — превращение размётки в `data:`-URL.
Виноват был один приём:

```js
binary += String.fromCharCode(...bytes.subarray(i, i + 0x8000));
```

Развернуть массив в аргументы кажется бесплатным, но на тридцати двух тысячах аргументов движок
уходит в медленный путь вызова. Те же байты кусками по 8 КБ через `apply` — 1.7 мс вместо 10.4 на
изолированном замере и −18 мс на живой странице. Итог: **27.8 мс вместо 45**, из них сборка 4.2,
декодирование SVG 21.9, перенос на холст 1.8.

Мораль не про base64. Бюджет уходил в место, которого не было ни в одной гипотезе, и нашёлся
только потому, что растеризатор с самого начала возвращает разбивку времени, а не одно число.

### Иллюстрации: вес платится на каждой странице главы

Картинка обязана быть `data:`-URI — внешние адреса внутри SVG-картинки не грузятся. Но в
композиторе лежит **глава целиком**, и в размётку каждой её страницы уезжали все иллюстрации
разом: пять картинок по 80 КБ — это лишние 400 КБ и лишние миллисекунды декодирования даже на
страницах, где картинок нет.

Решение: перед растеризацией картинки, не попавшие в текущую колонку, подменяются прозрачным
пикселем. Подмена безопасна ровно потому, что санитайзер проставляет каждой картинке `width` и
`height` при разборе: бокс задан атрибутами, а не содержимым, и вёрстка от подмены не шелохнётся.

Заодно иллюстрации ужимаются при разборе — до 1400 px по большей стороне, с пережатием в JPEG
поверх цвета бумаги. Скан на 3000 px в книге со страницей шириной 1024 px не даёт ничего, кроме
лишних килобайт в каждом кадре.

### Подрезка шрифтов оказалась не тем, чем казалась

SPEC §6.4 обещал снять зависимость бюджета от алфавита подрезкой шрифта до глифов конкретной
страницы через harfbuzz. При реализации выяснилось, что дешёвого способа узнать **текст
страницы** нет: браузер верстает колонки сам и наружу их содержимое не отдаёт, а разбирать
элементы по координатам дороже, чем экономия. Подрезка по главе — то, что доступно, — на главе в
двадцать тысяч знаков покрывает почти весь алфавит и почти ничего не экономит.

Так что зависимость от алфавита никуда не делась: латиница тянет 130 КБ шрифтов на страницу,
кириллица — 203 КБ. Запас на неё теперь есть (27.8 мс из 40), но взялся он из починки base64, а
не из подрезки. Вопрос перенесён в §21 спеки честной формулировкой.

### Переворот: две ошибки, которые ловятся только в движении

- **Пружина без цели.** Лист заводился в позу `t = from`, а цель ему выставлял только палец при
  отпускании. Переворот с клавиатуры оказывался в равновесии на первом же кадре, объявлял себя
  законченным и молча откатывался. Цель теперь ставится вместе с позой.
- **Защёлка «уже успокоился».** Флаг, чтобы не сообщать об окончании дважды, защёлкивался в тот
  единственный кадр, когда лист стоял в начальной точке без цели. Дальше он летел через всю
  книгу, но конца никто не ждал — страница зависала в воздухе. Флаг убран, идемпотентность
  перенесена в `endTurn`, который просто смотрит, есть ли ещё что заканчивать.
- **Упор на концах.** Резкий бросок уносил `θ` за `π`, и страница уходила сквозь левый блок вниз.
  Скорость ограничена сверху, положение — жёстким упором, гасящим только ту скорость, что толкает
  наружу.

Отдельно: перетаскивание считает угол **по точке захвата**, а не по внешнему краю листа
(`θ = acos(x / grip)`). Если мерить по краю, лист, взятый за середину, доходит от силы до двух
третей переворота, сколько его ни тяни, — курсору просто не хватает хода до края страницы.

### Зоопарк EPUB начинается сразу

На первых же собранных вручную книгах оглавление отвалилось целиком: NCX ссылался на
`text/one.html`, а манифест объявлял `Text/one.html`. Такая книга открывается везде, кроме
читалки, которая сравнивает строки как есть. Сопоставление путей теперь идёт по приведённой
форме — без якоря, без процентов, без регистра, — и та же поправка чинит второй частый случай:
`Ch3%20Notes.xhtml` в оглавлении против `Ch3 Notes.xhtml` в архиве.

### Замеры

Синтетическая книга на 513k знаков, 24 главы, десктопный профиль текстуры 1024×1453.

| Метрика | Значение | Бюджет |
|---|---|---|
| Полная вёрстка книги | 520–560 мс | < 2.5 с |
| Растеризация страницы | 27.8 мс (сборка 4.2 · декод 21.9 · холст 1.8) | < 40 мс |
| Живых текстур после 60 разворотов | 8 | ≤ 8 |
| JS heap там же | 21 МБ | — |
| Первая загрузка JS | 286 КБ gzip | < 350 КБ |

`jszip` и `marked` грузятся отдельными кусками и в первую загрузку не входят: разбор EPUB
начинается только когда файл действительно принесли.

Механика толщины на тех же настройках: 8 pt → 175 страниц → 8.8 мм, 10.5 pt → 287 → 14.4 мм,
16 pt → 673 → 33.7 мм.

## Структура

```
src/core/ingest/     zip, EPUB (OPF, spine, nav, NCX), txt, markdown
src/core/normalize/  санитайзер по белому списку, подготовка иллюстраций
src/core/paginate/   композитор и разбивка на страницы
src/core/rasterize/  SVG-растеризатор, подмножества шрифтов
src/scene/           three.js: процедурная книга, переворот, кэш текстур
src/ui/              воркспейс: панели, тулбар
src/store/           zustand
scripts/             загрузка шрифтов, генератор тестовых книг
```

`src/core` не знает ни про React, ни про three.js — там же будут жить документ тетради и сборка
снапшотов.
