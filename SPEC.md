# r3ad — спека

> 3D-читалка и 3D-блокнот. Пользователь загружает книгу — сайт считает её страницы, строит физически достоверный том нужной толщины, даёт его листать, конспектировать, ставить на полку и делиться стеллажом по ссылке.

**Статус:** черновик v1, готов к декомпозиции в задачи.
**Дата:** 2026-09-05

---

## 1. Что это

Три механики, вокруг которых собирается всё остальное:

1. **Том (Volume)** — загруженный файл превращается в 3D-книгу. Не «текстура книги», а настоящая пагинация: движок считает, сколько страниц занимает контент при текущем кегле, и строит блок страниц соответствующей толщины. Перелистывание — деформация геометрии, а не кроссфейд.
2. **Тетрадь (Journal)** — та же модель книги, но страницы редактируемые: рукописный ввод, текст, вставленные скриншоты, вырезки контента по ссылке.
3. **Стеллаж (Bookcase)** — тома и тетради анимированно уезжают на полки. Полку или весь стеллаж можно расшарить ссылкой в read-only.

Оболочка вокруг 3D-вьюпорта — воркспейс в духе Figma: левый навигатор, правый инспектор, нижний тулбар, командная палитра.

**Позиционирование для дев-профиля в X:** проект-витрина по трём темам сразу — процедурная 3D-геометрия, кастомизация материалов и нетривиальный рендер текста. Каждая веха (§20) заканчивается одним снимаемым на видео вау-моментом.

## 2. Зафиксированные решения

| Развилка | Решение | Почему |
|---|---|---|
| Хранение | **Local-first.** IndexedDB (метаданные, страницы, штрихи) + OPFS (блобы: исходники книг, картинки). Аккаунтов нет. | Мгновенный старт без регистрации, ноль стоимости хранения, приватность исходников по умолчанию. |
| Шеринг | Тонкий бэкенд. Кнопка «Поделиться» пакует снапшот и заливает его; всё остальное время сервер не участвует. | Ссылкой нельзя поделиться, если данные только в браузере. Но платить за хранение надо лишь за то, чем реально поделились. |
| Web3 | **Тип контента, не технология.** Ни кошельков, ни контрактов, ни токенов. X-треды, статьи и доки о протоколах импортируются как вырезки в тетрадь. | Так сформулировал заказчик. Убирает из MVP весь ончейн-риск, оставляя тематическую нишу и аудиторию. |
| Объём MVP | Широкий: читалка + тетрадь + стеллаж + шеринг. | Решение принято осознанно. Компенсируем узкими вехами (§20) — каждая вертикально завершена и демонстрируема. |
| Платформа | **Vercel** + Turso + Blob + Upstash. | Local-first почти не нагружает сервер, поэтому serverless тут дёшев и уместен. Ограничения платформы и обходы — §15.1; вся привязка изолирована в трёх файлах `src/server/`. |

**Явно вне скоупа v1:** аккаунты, синк между устройствами, коллаборация в реальном времени, книги с DRM (ACSM/Adept), мобильные приложения, оплата, ончейн-слой.

## 4. Пользовательские сценарии

### 4.1 Читатель
1. Открывает `/` → стеллаж, на полках демо-книги.
2. Кидает `.epub` в окно. Появляется пустая обложка, на ней прогресс: `парсинг → верстка → 320 страниц`.
3. Книга «прилетает» в центр и открывается на первом развороте.
4. Листает: колесо / стрелки / drag за угол страницы. Страница гнётся под курсором и падает по инерции.
5. В правом инспекторе двигает кегль → книга **перевёрстывается и физически толстеет на глазах**. Прогресс-метка на срезе едет.
6. Закрывает книгу — она улетает на свободный слот полки, корешок с названием встаёт в ряд.

### 4.2 Конспектирующий
1. `N` → создаётся тетрадь, ложится на стол раскрытой.
2. `B` → перо. Клик по странице → камера ложится фронтально, страница занимает вьюпорт, включается 2D-режим рисования с нажимом стилуса.
3. `Ctrl+V` скриншотом → картинка ложится на страницу карточкой, её можно двигать/крутить/ресайзить.
4. Вставляет ссылку на X-тред → бэкенд разворачивает её в вырезку → карточка треда ложится на страницу, дальше он обводит и подписывает её от руки.
5. `Esc` → камера возвращается, страница снова часть 3D-книги.

### 4.3 Делящийся
1. На полке жмёт «Поделиться».
2. Диалог: что кладём в снапшот (внешний вид полки / тетради целиком / тома целиком), публичность, опциональная парольная фраза.
3. Получает `r3ad.app/s/kq7f2m`. У себя остаётся `manageToken` — им можно обновить или снести снапшот.
4. Открывший ссылку видит ту же сцену в read-only и может «Форкнуть к себе» — снапшот скопируется в его локальную библиотеку.

Жёсткое правило: **ядро не знает про React и про three.js.** `Paginate`/`Rasterize`/`JournalDoc` тестируются в Node без браузера (кроме растеризации — она за интерфейсом `Rasterizer`, в тестах мок). Это единственный способ удержать проект такого объёма в тестируемом виде.

## 6. Пайплайн контента

Самая рискованная часть проекта. Разбирается на четыре независимые ступени с кэшем между ними.

```
файл/URL ──Ingest──> Source ──Normalize──> ContentDoc ──Paginate──> Page[] ──Rasterize──> Texture
```

### 6.1 Ingest — поддерживаемые входы

| Формат | Парсер | Поведение |
|---|---|---|
| EPUB 2 / 3 | `jszip` + собственный ридер OPF/NCX | Основной путь. Spine → главы, ресурсы в OPFS. |
| TXT / Markdown | `marked` | Тривиально. |
| PDF | `pdf.js` | **Без перевёрстки.** Страница PDF = страница книги 1:1, кегль не меняется. Инспектор это явно показывает. |
| FB2 | XML-парсер | После MVP. |
| DOCX | `mammoth` | После MVP. |
| DRM (ACSM, Adept) | — | Не поддерживается. Понятная ошибка с объяснением. |

### 6.2 Normalize → `ContentDoc`

Всё сводится к одному промежуточному представлению: последовательность блоков + карта ресурсов + метаданные + оглавление. HTML из EPUB прогоняется через whitelist-санитайзер (без скриптов, без внешних ссылок на ресурсы — только на локальные из архива).

### 6.3 Paginate — «книга считает свои страницы»

Ключевая механика. Не эмулируем типографику сами — **пользуемся движком браузера**:

1. Создаём скрытый `#compositor` — `<div>` с точными размерами страничного бокса в px при целевом DPI.
2. Внутрь кладём санитизированный контент главы, стили книги (шрифт, кегль, интерлиньяж, поля, переносы), и **`column-width` = ширине страницы**. Браузер сам режет контент на колонки.
3. `scrollWidth / columnWidth` = число страниц главы. Смещение i-й страницы = `i * (columnWidth + columnGap)`.
4. Собираем `Page[]` со ссылками «глава + смещение», якорями заголовков (для оглавления) и позицией в исходном тексте (для восстановления прогресса при перевёрстке).

Почему так: получаем настоящие переносы, вдовы/сироты, обтекание картинок и вертикальную ритмику бесплатно и корректно для любого языка.

**Ключ кэша пагинации:**
```
hash(contentHash, pageBoxW, pageBoxH, fontFamily, fontSizePx,
     lineHeight, margins, hyphenation, locale, ENGINE_VERSION)
```
Смена кегля = промах кэша = перевёрстка = **изменение физической толщины тома**. Это и есть тот самый демо-момент; перевёрстка книги на 400 страниц должна укладываться в ~400 мс, поэтому она идёт чанками по главам с прогрессом и не блокирует ввод.

**Геометрия из числа страниц:**
```
SHEET_THICKNESS = 0.10 мм         // офсетная бумага 80 г/м²
sheets          = ceil(pages / 2)
blockThickness  = sheets * SHEET_THICKNESS       // 400 стр ≈ 20 мм
leftBlock       = currentSheet * SHEET_THICKNESS // растёт по мере чтения
rightBlock      = blockThickness - leftBlock
```
Толщина срезов слева и справа привязана к прогрессу чтения — том выглядит «прочитанным наполовину» без единого элемента UI.

### 6.4 Rasterize — текст на 3D-странице

Три возможных подхода и выбранный компромисс:

| Подход | Плюсы | Минусы |
|---|---|---|
| DOM-оверлей / CSS3DRenderer | настоящий текст, выделение, a11y | не гнётся, не освещается, ломает изгиб страницы |
| Растр в текстуру | полная свобода шейдера, любой изгиб | не выделяется, память, чёткость на зуме |
| SDF-текст (`troika-three-text`) | резкость на любом зуме | сложная вёрстка (картинки, инлайн-стили) фактически невозможна |

**Решение: «растр в движении, DOM в покое».**

- Пока идёт анимация, зум или поворот камеры — страницы это текстуры. Изгиб, тени, преломление — всё работает.
- Как только сцена успокоилась и камера смотрит на разворот, поверх двух видимых страниц подставляется DOM-слой (`<Html transform occlude>` из drei) с тем же контентом. Текст становится выделяемым, копируемым, ищется через Ctrl+F, доступен скринридеру.
- Первое же событие листания снимает DOM-слой и возвращает текстуры. Переход не виден, потому что растр — пиксель-в-пиксель тот же композитор.

**Как получается растр:** `foreignObject` в SVG → `Image` → 2D-холст → `CanvasTexture`. Быстрее `html2canvas` и точнее его.

Путь узкий: **проверено на M0**, четыре условия, каждое из которых при нарушении ломает результат молча, без единой ошибки в консоли.

| Условие | Что происходит при нарушении |
|---|---|
| Адрес SVG — только `data:` | С `blob:` картинка считается cross-origin, `texImage2D` падает с SecurityError |
| Приёмник — 2D-холст, не `ImageBitmap` | `createImageBitmap` от SVG теряет origin-clean даже когда сам `<img>` его сохранил |
| `font-display: swap` во вшитых `@font-face` | При `block` и при `auto` текст не рисуется вообще — страница выходит чистым фоном |
| Шрифты инлайнятся как base64 woff2 | Гарнитуры из `document.fonts` внутри SVG-картинки не видны, текст молча уходит в запасной serif |

Все картинки — тоже data-URI. Для нас это бесплатно: ресурсы уже лежат локально в OPFS. Ещё один аргумент за local-first.

**Вес шрифтов — главная статья расхода растеризации.** Вшивать весь набор значит платить ~460 КБ за страницу, поэтому подмножества выбираются по двум осям: какие символы на странице есть (кириллица и латиница, но не греческий) и какие начертания (курсив только там, где он реально встречается).

Сколько остаётся — зависит от алфавита, и разница измерима: страница латиницей тянет 130 КБ и растеризуется за 28–37 мс, та же страница с кириллицей — 203 КБ и больше 70 мс. Бюджет в 40 мс, таким образом, сейчас держится на языке контента, а не на конвейере. Следующий шаг снимает эту зависимость: подрезка шрифта до глифов конкретной страницы через harfbuzz-subset, ожидаемо ~10 КБ вместо 130–200.

**Лицензии шрифтов:** встраивание = дистрибуция файла, поэтому только SIL OFL. Базовый набор: **Literata** (текст книги, спроектирована под чтение), **Inter** (интерфейс), **JetBrains Mono** (код в статьях и вырезках). Опциональные пресеты: EB Garamond, Source Serif, Atkinson Hyperlegible (для режима повышенной читаемости).

### 6.5 Кэш текстур

Живут только `текущий разворот ± 2`. LRU, немедленное `.dispose()` при вытеснении. Предрастеризация вперёд — в `requestIdleCallback`, с отменой при быстром листании.

| Профиль | Размер страницы | Байт с мипами | Живых | Итого VRAM |
|---|---|---|---|---|
| Desktop | 1024×1448 | ~7.9 МБ | 6 | ~48 МБ |
| Desktop zoom-in | 1536×2172 | ~17.8 МБ | 2 | +36 МБ (временно) |
| Mobile | 768×1086 | ~4.4 МБ | 4 | ~18 МБ |

Утечка текстур страниц — риск №1 по памяти. В дев-режиме — HUD-счётчик живых текстур, в CI — тест «пролистать 200 страниц, живых текстур ≤ 8».

## 7. 3D

### 7.1 Модель книги — процедурная

Никаких внешних GLB. Вся геометрия генерируется, потому что она обязана меняться от числа страниц и от настроек кастомизации.

```
Book
├─ CoverFront   (BoxGeometry, скруглённые углы, толщина 2.5 мм)
├─ CoverBack
├─ Spine        (изогнутая полоса; радиус зависит от blockThickness)
├─ PageBlockL   (Box + текстура среза; ширина = leftBlock)
├─ PageBlockR
├─ PageL        (плоскость 32×2 сегмента, шейдер изгиба)
├─ PageR
├─ FlippingPage (0–2 штуки, только во время анимации)
└─ Ribbon       (закладка, опционально)
```

Текстура среза — процедурный шум с горизонтальной анизотропией: даёт узнаваемую «слоистость» бумаги без геометрии на 400 листов.

### 7.2 Шейдер перелистывания

Плоская страница, гнущаяся по цилиндру, плюс поворот вокруг корешка. `t ∈ [0,1]` — прогресс.

```glsl
// θ — поворот вокруг корешка
float theta = t * PI;
// r — радиус изгиба: бесконечен в покое, минимален в середине переворота
float r = mix(R_FLAT, R_CURL, sin(t * PI));

// цилиндрическая деформация вдоль X (0 у корешка → 1 у внешнего края)
float a = x / r;
p.x = r * sin(a);
p.z = r * (1.0 - cos(a));

// трепет листа: тем сильнее, чем дальше от корешка и ближе к середине переворота
p.z += FLUTTER * sin(y * 3.0 + t * 8.0) * x * sin(t * PI);

// финальный поворот вокруг оси корешка
p = rotateY(p, theta);
```

Детали, без которых анимация выглядит дёшево:
- **Двусторонность.** Одна геометрия, в фрагментном шейдере `gl_FrontFacing` выбирает текстуру лицевой или оборотной стороны. Оборот зеркалится по X.
- **Просвет.** Бумага полупрозрачна: при подсветке сзади сквозь страницу слабо проступает текстура оборота (`mix` по `NdotL`).
- **Контактная тень** от переворачивающейся страницы на нижележащую — отдельный дешёвый blob-shadow, не shadowmap.
- **Инерция.** Отпустил страницу на середине — она либо дошлёпывает, либо падает обратно, по знаку скорости. Пружина, не линейный твин.
- **Drag за угол.** Raycast по плоскости страницы даёт `t` напрямую от курсора — страница слушается пальца, а не проигрывает ролик. Это ощутимо отличает проект от типовых демок.

### 7.3 Стеллаж

- `Bookcase → Shelf[] → Slot[]`, полки процедурные (доски + задняя стенка), количество и шаг настраиваются.
- Корешки на полке — **инстансированные**: одна геометрия, per-instance цвет/толщина/наклон. Полная модель книги подгружается только для той, которую вытаскивают.
- **Корешок генерируется сам:** ширина ∝ числу страниц, цвет — доминанта обложки (или заданный), название — `troika-three-text` вдоль корешка с автоподбором кегля, тиснение — anisotropy + слабый emissive.
- Анимация «на полку»: путь по кривой Catmull-Rom (вверх-дугой), одновременный доворот из «раскрытой» позы в «закрытую», ~900 мс, `easeInOutCubic`, посадка с микро-отскоком.
- Клик по корешку → книга наклоняется наружу, второй клик → вытаскивается и раскрывается.
- Свободные слоты подсвечиваются при драге книги; порядок на полке меняется перетаскиванием.

## 8. Кастомизация

То, ради чего в профиле вообще заводится 3D. Всё — параметры материала, ноль ассетов.

**Книга:** материал обложки (ткань / кожа / картон / супер-обложка), базовый цвет, тиснение (золото / серебро / блинт / без), скругление углов, потёртость, окраска среза (`sprayed edges` — сплошная, градиент, мрамор), тон бумаги (белая / кремовая / состаренная), плотность бумаги (влияет на толщину!), лента-закладка, каптал.

**Тетрадь:** тип разлиновки (чистая / линейка / клетка / точки / нотный стан), шаг разлиновки, пружина вместо корешка, перфорация, обрез уголков.

**Стеллаж:** порода дерева, тон, число полок и их шаг, задняя стенка, свет (тёплая лампа / дневной / вечер / студия), сила теней, глубина резкости.

Все пресеты сериализуются в объект `Theme` — он входит в снапшот, поэтому расшаренная полка выглядит у получателя ровно так же.

## 9. Тетрадь

### 9.1 Ключевое решение: рисуем в 2D, показываем в 3D

Рисование напрямую по 3D-поверхности через raycast — неточное, теряет нажим и наклон стилуса, ломается на изогнутой странице. Поэтому:

**Клик пером → камера ложится фронтально, страница разворачивается плоско и занимает вьюпорт → включается обычный 2D canvas поверх.** Рисование идеально точное, с `PointerEvent.pressure` и `tiltX/tiltY`, `getCoalescedEvents()` для гладких линий на 120 Гц. `Esc` — камера возвращается, холст становится текстурой страницы.

Переход — 350 мс, читается как «наклонился к тетради».

### 9.2 Документ страницы

Страница тетради — слоёный документ, **не растр**:

```
PageDoc
├─ background: ruled | grid | dots | blank | staff
├─ layers[]
│   ├─ StrokeLayer  — векторные штрихи
│   ├─ BlockLayer   — текстовые блоки, картинки, вырезки
│   └─ (порядок, видимость, блокировка — как в Figma)
```

Штрих хранится вектором: `{ brush, color, width, points: [x, y, pressure, t][] }`. Причины: расшариваемый размер (тысяча штрихов ≈ десятки КБ против мегабайтов PNG), перерисовка в любом разрешении при зуме, честный undo, и на будущее — «проигрывание» конспекта как анимации.

Сглаживание — Catmull-Rom по точкам, ширина сегмента ∝ нажиму, рендер в кривые Безье на canvas 2D.

### 9.3 Инструменты

`V` выбор · `B` перо · `H` маркер (multiply) · `E` ластик (по штрихам, не по пикселям) · `T` текст · `I` картинка · `L` вырезка по ссылке · `Space` панорама.

Undo/redo — общий `CommandStack` на всю тетрадь, каждая команда сериализуема (нужно и для undo, и для будущей коллаборации).

### 9.4 Вставка изображений

`Ctrl+V` / drag-n-drop / загрузка. Блоб уходит в OPFS под ключом `sha256`, страница ссылается на хэш — один и тот же скриншот на десяти страницах хранится один раз. Ресайз, поворот, кроп, лёгкая «полароидная» рамка, тень.

## 10. Импорт по ссылке

Браузер не может тянуть произвольные URL (CORS), поэтому — эндпоинт `POST /api/unfurl`, который приводит любую ссылку к общему виду.

**Адаптеры:**

| Адаптер | Источник | Что достаёт |
|---|---|---|
| `x-post` | пост или тред в X | автор, аватар, текст, медиа, дата, ветка треда целиком |
| `article` | статьи, блоги, доки | Readability → заголовок, автор, текст, картинки |
| `og-card` | всё остальное | OG/Twitter-теги → карточка |
| `image` | прямая ссылка на картинку | сама картинка |
| `paste-fallback` | нет доступа, приватный аккаунт, блок по IP | пользователь вставляет текст руками, форматирование и атрибуция сохраняются |

`paste-fallback` — **равноправный путь, а не аварийный.** Функции ходят с датацентрового IP, X такие блокирует агрессивнее домашних (§15.1), так что ручная вставка обязана быть удобной сама по себе: распознавание автора и даты из вставленного текста, drag-n-drop скриншота поста рядом.

Каждый адаптер возвращает единый `Clipping`, дальше он либо ложится карточкой на страницу тетради, либо (несколько штук) собирается в отдельный **скомпилированный том** — «досье» из вырезок, которое верстается и листается как обычная книга.

**Сценарий, ради которого это делается (web3):** пользователь неделю собирает треды, статьи и куски доков про протокол, обводит и комментирует их от руки в тетради, потом делится одной ссылкой на полку с этим досье. Ниша: исследователи протоколов, DeFi-аналитика, аудиторы, ведущие рисёрч-тредов.

**Правила адаптеров:** атрибуция и ссылка на оригинал рендерятся всегда и не отключаются; кэш ответа 24 ч; таймаут 8 с; лимит ответа 5 МБ; строгий SSRF-фильтр (запрет приватных диапазонов, `file://`, редиректов на них); рейт-лимит по IP.

## 11. Шеринг

### 11.1 Два уровня

- **`?s=<base64url>`** — до ~1.5 КБ. Настройки сцены, тема, компоновка полки, ссылка на один внешний контент. Без сервера вообще.
- **`/s/:id`** — снапшот. Всё, что больше: содержимое тетради, картинки, тома.

### 11.2 Что попадает в снапшот

Диалог явно спрашивает объём, дефолт — минимальный:

1. **Только внешний вид** (дефолт) — корешки, обложки, названия, тема стеллажа. Контент не выгружается.
2. **Тетрадь целиком** — страницы, штрихи, вложенные картинки, вырезки.
3. **Том целиком** — исходный текст книги. Отдельный тоггл с предупреждением (см. §18).

### 11.3 Механика

```
1. Клиент  собрать манифест, посчитать sha256 всех ассетов
2. Клиент → POST /api/assets/negotiate { hashes[] }
3. Сервер → { missing: [...], uploadTokens: {...} }   // каких нет + токены на заливку
4. Клиент → PUT напрямую в blob storage, минуя функции   ⬅ важно, см. §15.1
5. Клиент → POST /api/share { manifest, assetHashes[] }
6. Сервер → { id: "kq7f2m", manageToken }
7. Клиент  сохранить manageToken локально → это и есть «владение» без аккаунта
```

Шаг 4 идёт мимо бэкенда не для красоты: тело запроса к serverless-функции ограничено 4.5 МБ, а ассеты бывают до 10 МБ. Проксировать их через функцию нельзя в принципе (§15.1).

- Снапшоты **иммутабельны и версионируются**: «Обновить» создаёт новую версию под тем же `id`.
- Приватность: unlisted по умолчанию, `noindex`.
- Опциональный пароль: контент шифруется на клиенте (AES-GCM), ключ живёт **во фрагменте URL** `#k=...` — во фрагменте, потому что он не уходит на сервер. Сервер хранит только шифротекст.
- «Форкнуть к себе» — снапшот копируется в локальную БД получателя и дальше живёт у него.
- Экспорт/импорт `.r3ad` (zip: `manifest.json` + `assets/`) — тот же формат, что и снапшот. Полный оффлайн-бэкап без сервера.

## 13. Модель данных

```ts
type ID = string; // nanoid(12)

// ─── Книги ────────────────────────────────────────────────────
interface BookBase {
  id: ID;
  kind: 'volume' | 'journal';
  title: string;
  author?: string;
  createdAt: number;
  updatedAt: number;
  theme: Theme;
  shelfRef?: { shelfId: ID; slot: number };
  progress: { sheet: number; anchor?: string }; // anchor переживает перевёрстку
}

interface Volume extends BookBase {
  kind: 'volume';
  source:
    | { type: 'file'; format: 'epub' | 'pdf' | 'txt' | 'md'; blobKey: string }
    | { type: 'compiled'; clippingIds: ID[] };
  contentHash: string;
  pagination?: PaginationResult; // кэш, инвалидируется по ключу
}

interface Journal extends BookBase {
  kind: 'journal';
  pageIds: ID[];
  defaultBackground: PageBackground;
}

// ─── Пагинация ────────────────────────────────────────────────
interface PaginationResult {
  key: string;         // hash(contentHash, pageBox, typography, ENGINE_VERSION)
  pageCount: number;
  sheetCount: number;
  thicknessMm: number;
  pages: PageRef[];
  toc: TocEntry[];
}
interface PageRef { index: number; chapterId: string; columnOffset: number; anchor?: string }

// ─── Страница тетради ─────────────────────────────────────────
interface PageDoc {
  id: ID;
  journalId: ID;
  index: number;
  background: PageBackground;
  layers: Layer[];
}
type Layer =
  | { id: ID; type: 'strokes'; visible: boolean; locked: boolean; strokes: Stroke[] }
  | { id: ID; type: 'blocks';  visible: boolean; locked: boolean; blocks: Block[] };

interface Stroke {
  id: ID;
  brush: 'pen' | 'marker' | 'pencil';
  color: string;
  width: number;
  points: [x: number, y: number, pressure: number, t: number][];
}

type Block =
  | { id: ID; type: 'text'; rect: Rect; rot: number; html: string; style: TextStyle }
  | { id: ID; type: 'image'; rect: Rect; rot: number; assetHash: string; crop?: Rect; frame?: 'none' | 'polaroid' }
  | { id: ID; type: 'clipping'; rect: Rect; rot: number; clippingId: ID };

// ─── Вырезки ──────────────────────────────────────────────────
interface Clipping {
  id: ID;
  url: string;
  adapter: 'x-post' | 'article' | 'og-card' | 'image' | 'paste';
  fetchedAt: number;
  title?: string;
  author?: { name: string; handle?: string; avatarHash?: string };
  body: ContentBlock[];      // общий нормализованный формат
  media: { assetHash: string; alt?: string }[];
  attribution: { sourceName: string; sourceUrl: string }; // всегда рендерится
}

// ─── Стеллаж ──────────────────────────────────────────────────
interface Bookcase { id: ID; title: string; shelves: Shelf[]; theme: Theme }
interface Shelf { id: ID; label?: string; capacity: number; items: (ID | null)[] }

// ─── Тема ─────────────────────────────────────────────────────
interface Theme {
  cover: { material: 'cloth' | 'leather' | 'board' | 'jacket'; color: string;
           foil: 'gold' | 'silver' | 'blind' | 'none'; wear: number };
  paper: { tint: string; gsm: number; edge: 'plain' | 'sprayed' | 'gilded'; edgeColor?: string };
  type:  { family: string; sizePx: number; lineHeight: number; margins: Margins; hyphens: boolean };
  scene: { preset: 'lamp' | 'daylight' | 'evening' | 'studio'; exposure: number;
           shadows: number; dof: number; wood: string };
}

// ─── Снапшот ──────────────────────────────────────────────────
interface Snapshot {
  id: string;              // короткий, kq7f2m
  version: number;
  scope: 'appearance' | 'journal' | 'volume' | 'shelf' | 'bookcase';
  encrypted: boolean;
  payload: unknown;        // или шифротекст, если encrypted
  assets: string[];        // sha256
  createdAt: number;
}
```

## 14. API

Пять эндпоинтов. Больше в v1 не нужно. Все — Node runtime (не Edge: нужны `dns` для SSRF-фильтра и полноценный `Buffer`).

| Метод | Путь | Назначение | Тело |
|---|---|---|---|
| `POST` | `/api/unfurl` | `{ url }` → `Clipping`. Кэш 24 ч в Upstash, SSRF-фильтр, рейт-лимит. | мал. |
| `POST` | `/api/assets/negotiate` | `{ hashes[] }` → `{ missing[], uploadTokens }`. Дедуп + выдача прав на прямую заливку. **Сам файл сюда не идёт.** | мал. |
| `POST` | `/api/share` | `{ manifest, assetHashes[] }` → `{ id, manageToken }`. С `?id=` — новая версия (нужен токен). Манифест ≤ 2 МБ; всё тяжёлое уже лежит в blob. | ≤ 2 МБ |
| `GET` | `/api/share/:id` | **302 на blob-URL снапшота** + короткие метаданные в заголовках. Публично, `noindex`. | редирект |
| `DELETE` | `/api/share/:id` | Удаление по `manageToken`: запись в Turso + удаление осиротевших блобов. | мал. |

Ни один эндпоинт не пропускает через себя байты пользовательских файлов — они ходят браузер ↔ blob storage напрямую. Это не оптимизация, а обязательное условие (§15.1).

**Лимиты:** снапшот ≤ 50 МБ суммарно, ассет ≤ 10 МБ, манифест ≤ 2 МБ, 20 снапшотов/сутки с IP, unfurl 60/час с IP. Счётчики — в Upstash, потому что инстансы функций не разделяют память.

**TTL:** 90 дней с продлением при каждом открытии. Чистка — Vercel Cron раз в сутки: помечает протухшие, удаляет блобы без ссылок.

## 15. Стек и структура

**Клиент:** Next.js (App Router) · TypeScript strict · React Three Fiber + drei · Zustand · Tailwind + Radix · Dexie · jszip · pdf.js · troika-three-text · zod.
**Сервер:** Vercel Functions (Next route handlers, Node runtime) · Mozilla Readability + `linkedom` для unfurl.
**Инфра:** **Vercel** (хостинг + функции + CDN + Cron) · **Turso** (libSQL — снапшоты, `manageToken`, ссылки на ассеты) · **Vercel Blob** (ассеты и payload снапшотов) · **Upstash Redis** (рейт-лимиты, кэш unfurl).
**Тесты:** Vitest (ядро) · Playwright (сценарии + скриншотные тесты сцены).

Почему Turso, а не Postgres: диалект тот же SQLite, но доступ по HTTP — значит работает из stateless-функции без пула соединений. Модель данных из §13 переезжает без переписывания.

### 15.1 Ограничения Vercel и как они учтены

Serverless-платформа накладывает четыре жёстких рамки. Все они учтены в §11.3 и §14 — здесь они собраны в одном месте, чтобы их не «починили» обратно при рефакторинге.

| Ограничение | Что ломается наивно | Решение в спеке |
|---|---|---|
| **ФС эфемерная и read-only** (кроме `/tmp` на время инвокации) | `better-sqlite3` с файлом на диске: база исчезает между вызовами | Turso по HTTP |
| **4.5 МБ на тело запроса и ответа функции** | `PUT /api/assets/:sha256` с файлом до 10 МБ; отдача снапшота на 50 МБ через `GET` | Прямая заливка клиент → blob по токену; `GET /api/share/:id` отдаёт **302**, а не payload |
| **Инстансы не делят память** | Рейт-лимит счётчиком в модуле — обходится простым параллельным запросом | Счётчики в Upstash |
| **Лимит времени функции** (Hobby ~10 с, настраивается до 60 с; Pro — больше) | Долгая обработка на сервере | Её нет: парсинг, пагинация и растеризация целиком в браузере. Серверу остаётся unfurl с таймаутом 8 с — укладывается даже в Hobby |

Два нюанса, не архитектурных, но влияющих на планирование:

- **Unfurl ходит с датацентрового IP.** X такие блокирует агрессивнее, чем домашние. Поэтому `paste-fallback` из §10 проектируется не как аварийный путь, а как равноправный: пользователь вставляет текст поста руками, форматирование и атрибуция сохраняются. Автоматический `x-post` — приятный бонус, когда срабатывает.
- **Hobby-тариф — только некоммерческое использование.** Для дев-профиля подходит; при появлении оплаты нужен Pro.

**Переносимость.** Vercel-специфичного кода — три файла: выдача токенов на заливку, клиент Turso, клиент Upstash. Всё за интерфейсами `BlobStore`, `MetaStore`, `RateLimiter`. Переезд на docker с томом и SQLite (тогда прямая заливка не нужна, но и не мешает) — замена трёх реализаций, не переписывание бэкенда.

**Переменные окружения:**
```
TURSO_DATABASE_URL, TURSO_AUTH_TOKEN
BLOB_READ_WRITE_TOKEN
UPSTASH_REDIS_REST_URL, UPSTASH_REDIS_REST_TOKEN
NEXT_PUBLIC_APP_ORIGIN        # для канонических ссылок /s/:id
```

## 17. Доступность и деградация

3D-читалка без альтернативы — читалка, недоступная части людей. Поэтому:

- **Плоский режим** (`?mode=flat` и тоггл в шапке) — тот же `ContentDoc`, отрендеренный обычным HTML. Стоит почти ничего: композитор уже выдаёт DOM. Это и a11y-путь, и режим «просто дай почитать», и SEO для публичных снапшотов.
- DOM-слой в покое (§6.4) делает основной режим доступным скринридеру и `Ctrl+F`.
- Полная навигация с клавиатуры, видимый фокус, `prefers-reduced-motion` (переходы страниц становятся мгновенными, парение книг отключается).
- Нет WebGL2 / слабая GPU → автоматически плоский режим с внятным баннером.
- Все действия мышью дублируются в командной палитре.

## 18. Правовое и безопасность

Проект принимает пользовательские файлы книг и раздаёт ссылки — это надо развести аккуратно, иначе сервис превращается в файлообменник пиратских книг.

- **Загруженные файлы по умолчанию не покидают браузер.** На сервере их нет.
- Шеринг тома **целиком** — отдельный тоггл с прямым предупреждением: «вы публикуете содержимое файла; делайте это только со своим текстом или с тем, что разрешено распространять».
- Дефолтный объём шеринга — «только внешний вид»: корешки и обложки, без содержимого.
- Публичная страница `/s/:id` показывает источник и кнопку «Сообщить о нарушении»; эндпоинт удаления по жалобе; лог удалений.
- Вырезки всегда несут атрибуцию и ссылку на оригинал; текст статей хранится усечённым (превью + ссылка), не полной копией.
- Санитайзинг всего HTML из EPUB и unfurl (whitelist тегов/атрибутов, запрет `script`, `iframe`, `on*`, `javascript:`).
- SSRF-фильтр в unfurl: DNS-резолв до запроса, отсечение приватных диапазонов, запрет редиректов наружу whitelist-схем.
- Снапшоты — `noindex`, ссылки неугадываемые (nanoid 12), опциональное шифрование на клиенте.
- CSP без `unsafe-eval`; ассеты — с отдельного origin.

## 21. Открытые вопросы

1. **Домен и имя.** `r3ad` читается как read и как r3f. Оставляем? Домен свободен?
2. **Демо-контент.** Нужны 5–6 книг в общественном достоянии с приличной вёрсткой (Gutenberg / Standard Ebooks) — они грузятся при первом входе, чтобы пустой стеллаж никого не встречал.
3. **PDF в MVP или после?** Он не перевёрстывается и ломает главную механику «толщина зависит от кегля». Склоняюсь к M4+, с честной пометкой в UI.
4. ~~**X-адаптер.**~~ Решено: `paste-fallback` — основной путь, автоматический `x-post` (oEmbed) пробуется первым и деградирует молча. Причина — блокировка датацентровых IP, §15.1.
5. **Лимит размера книги.** 50 МБ EPUB с картинками — верстать целиком или подгружать главами? Предлагаю порог 20 МБ: выше — ленивая пагинация по главам с оценкой общего числа страниц.
6. **Мобильный ввод.** Рисование пальцем без стилуса — делать ли отдельный режим со сглаживанием и увеличением, или на мобильном тетрадь read-only в v1?
7. **Потолок трафика.** Если расшаренный стеллаж залетит в X, бесплатный тир Vercel/Blob кончится за часы, а тарификация — по факту. Нужен предохранитель до M5: жёсткий дневной лимит на отдачу с автоматической деградацией публичной страницы в плоский режим, либо биллинг-алерт с ручным рубильником. Решить, что именно, при реализации шеринга.
